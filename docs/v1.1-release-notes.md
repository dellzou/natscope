# NatScope v1.1.0

> 发布日期：2026-11-12
> 上一版：v1.0.0

## 请优先升级

v1.0.0 在**部分网络环境**下会给出方向性错误的 NAT 类型结论，方向是**高估** P2P 可用性。

具体表现：在受限锥型 / 端口受限锥型的网络上，被误报为「完全锥型」——让你以为 P2P 联机、BT、远程访问都能直接打通。

是否触发取决于**所连的 STUN 服务器**：同一台机器、同一天，换台服务器结论就可能不同。也就是说 v1.0.0 的结论**不稳定、不可复现**，这也是很多用户感觉"这工具时灵时不灵"的原因。

**如果你之前在 v1.0.0 里看到「完全锥型 NAT」，v1.1.0 可能显示「端口受限锥型」。这不是变差了，而是变准了。**

## 修了什么

以下问题在 v1.0.0 上都能复现，v1.1.0 已全部修正，并新增 10 条回归用例锁定（这些用例在 v1.0.0 上有 14 条断言失败）：

| 问题 | 用户感受 |
|---|---|
| 受限锥型 / 端口受限锥型被误报为「完全锥型」 | 以为 P2P 联机、BT、远程访问都能直接打通 |
| 部分企业网络或防火墙严格的网络只放行少量 STUN 服务器时，显示「无法判定」 | 拿不到任何结论 |
| 局域网上有设备返回异常响应时，命令行版崩溃、界面版丢弃已算完的结果 | 检测中断，白等一轮 |
| 一次网络丢包就可能把「完全锥型」降级成「受限锥型」 | 把好结果说成坏结果 |
| 服务器换了错误提示的措辞后，「端口受限锥型」判定永久失效且无提示 | 结论静默变差 |
| 服务器根本不支持某项测试时，被误判成「端口受限锥型」 | 白折腾端口映射 |
| 偶尔一次网络抖动，就可能把结论误报成「对称型 NAT」 | 以为必须开端口映射或改用中继 |

### 一个技术说明（如果你关心实现）

过滤行为的测量要依赖 STUN 服务器的 `CHANGE-REQUEST` 属性。旧版为了让「服务器是否支持该属性」和「NAT 放不放行」两个判断共用一条通道，导致两者互相污染——**测服务器能力的包，改变了测 NAT 行为的结果**。

v1.1 把它拆成三个独立通道：采样、能力诊断、行为测量，各自独立 socket，互不可见。这也是为什么结论现在连续多轮一致。

## 界面

- 结果页重做：新增 **行为矩阵**（3×3，一眼看出映射与过滤的组合落在哪一格）、**类型谱**（5 类锥型/对称型横向对比，当前类型有标记）、**场景可用性徽章**（游戏联机 / BT / 远程访问 / 语音视频 是否可用）
- 报告导出升级：JPG 报告不再裁剪内容，新增上述图形块；TXT 报告新增行为矩阵与场景章节
- 修复 1366×768 等小屏 + 125% 缩放下**底部按钮被任务栏挡住**的问题
- 窗口尺寸与位置会记忆，下次启动恢复

## 已知边界（不是缺陷，是本版不做的范围）

**1. exe 不支持命令行参数**

`NatScope.exe --txt out.txt` 不会生效——双击就是图形界面。命令行能力仅限源码调用 `python -m natscope.cli`。计划在 v1.2 补。

**2. JPG 报告依赖系统中文字体**

使用系统已安装的微软雅黑 / 黑体。**非中文版 Windows 上中文可能显示为方块，请优先使用导出的 TXT 报告。**

**3. 不支持纯 IPv6 网络**

当前只测 IPv4 出口。纯 IPv6 环境下会提示无可用服务器。

## 这一版没有改的东西

- **检测原理没变**：仍然基于 RFC 3489 / RFC 5780 的 STUN 探测，不发任何非 STUN 流量
- **内置服务器池没变**：仍是去重后的 91 个公共 STUN 服务器
- **不会上传任何数据**：只向用户选定的 STUN 服务器与本地网关发包，无遥测

## 关于可用服务器数量

升级后你可能发现「可用服务器」比上一版少。两个原因，都不是砍了可用节点：

1. **公共 STUN 服务器本身在浮动**：同一批地址在不同时段会有 51~63 台可用，掉线恢复很频繁。跨时间点比数量没有意义。
2. **本版对畸形响应更严格**：实测 91 台里**被规则拒绝的是 0 台**，减少的都是"当时确实连不上"的。
