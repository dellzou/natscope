# 判定启发式与测试纪律

> 本文记录 NatScope 判定链路里**几处不能靠"看代码就懂"的取舍**，以及一条从三次
> 真实事故里总结出来的测试纪律。改 `natscope/nat.py` 之前请先读这一页。
>
> 涉及代码：`natscope/nat.py` 的 `run()` / `_measure_filtering()` /
> `_recheck_outlier_samples()` / `_mapping_mode()` / `_is_routable()`。

---

## 一、为什么要三个 socket：两个方向相反的污染

NAT 的过滤表是**按「本地 socket ── 也就是内部端口」记账**的，这是全部结论的基础：

> 一条通道朝某个 `ip:port` 发过包 → 只在这条通道的白名单里留下那条记录，
> 换一条 socket 就是一本新账。

围绕这一点，历史上出过两个方向相反的 bug：

| 编号 | 现象 | 机理 | 误判方向 |
|---|---|---|---|
| P0-1 | 受限锥型被判成**完全锥型** | 采样先朝 `OTHER-ADDRESS` 发包（为读属性），给测量通道开了白名单；随后 Test II 的回包恰好从该地址回来，被放行 | 高估可用性（最危险） |
| P1-18 | EIM 被判成**对称型** | 反方向：先发 CHANGE-REQUEST，被它打过的服务器地址族，后续映射被 NAT 重新分配端口，采样拿到的端口与 Test I 不一致 | 低估可用性 |

两者都"偶尔"出现，取决于当次选中哪台服务器 —— 对诊断工具来说，「同一个网络两次
点击答案不同」比稳定地错更糟。所以现在用三通道结构性隔离：

```
socket A（采样）   Test I → 多目标采样(含 OTHER-ADDRESS) → 离群复核 → close
socket C（能力）   Test I → 预热 → CHANGE change_port    → close   （惰性，仅双超时路径）
socket B（测量）   plain Binding(建映射) → Test II → Test III → close
```

再加一条**铁律**：任何 CHANGE-REQUEST 都不得早于任何一次采样完成。socket 隔离已经
足够，顺序约束是第二道保险 —— 不依赖任何人"记得"要按什么顺序写。

## 二、启发式：映射端口"多数判据"

**判据**：把样本按公网出口 IP 分组，取样本最多的那一组；组内若有 ≥2 个样本的映射
端口相同、且不一致的样本**最多一个**，判为 `EIM`（端点无关映射）。

**为什么可以这么做**：离群值几乎总是测量伪影——典型来源是「该目的地址刚被
CHANGE-REQUEST 碰过，NAT 给它重新分配了端口」，以及多 WAN 出口造成的
"同一 socket 走了不同线路"。这些都不是"映射随目的变化"，而 EIM 的定义恰恰是
"端口被复用"。

**代价 / 什么时候会失效**：真对称型（APDM）下每个目的各持一个端口，正常凑不出多数，
会正确落到 APDM 判定。**但**如果真对称型里恰好有两个目的撞上同一个公网端口，
多数判据会把它们当成"一致的多数"，从而误判成 EIM。端口空间 64512、样本 5~7 个，
数量级约万分之一，可以接受；但这是**假设**，长期应观察是否有反例上报。

**配套的复核**：发现唯一离群样本时，`_recheck_outlier_samples()` 会在**采样 socket**
上对该目的重发一次（`attempts=2`）。重测与多数一致 → 丢弃异常值并记 note
（说明原值是伪影）；仍不一致 → 保留并记 warning（此时才可能是真的 APDM）。
正常 EIM 环境下这一层零额外开销（不触发）。

**多 WAN 保护**：若不同样本的公网出口 IP 不一致，只比对同一出口的样本。多线环境下
"端口不同"是出口不同造成的，拿它当对称型证据会误判；本机（双出口）实测因此从
APDM 纠正为 EIM。

### 关于 `_is_routable()`：**不要**换成 `ipaddress.is_private`

Python 3.10+ 的 `is_private` 把 TEST-NET / 文档保留段（`192.0.2.0/24`、
`198.51.100.0/24`、`203.0.113.0/24`）也算作私有：

```
203.0.113.5    → is_private=True    （但 _is_routable → True，正确）
198.51.100.7   → is_private=True
10.10.0.62     → is_private=True    （_is_routable → False，正确）
```

换成 `is_private` 会把所有用这些地址写夹具的单元测试误杀，也会砍掉真实的边缘地址。
`_is_routable()` 用显式网段白名单，语义就是"这个地址能不能真的发到公网去"。

## 三、启发式：能力必须"自证"，证明者必须等于测量者

判断 APDF（端口受限）需要两个事实同时成立：Test II 与 Test III **都超时**，
且这台服务器**确实会**响应 `change_port`。第二个事实只能靠"预热一次性 socket 再发一次
`change_port`"来取得（预热是为诊断能力，不是测 NAT —— 两件事必须分开）。

**关键约束：不许跨服务器推断。** 「A 会响应 change_port」**不能**证明「B 的两次超时
是 NAT 挡的」——B 自己没实现 change_port 也会两次超时。拿 A 的证据判 B 的 APDF，
等于给用户的网络扣一顶莫须有的帽子（这是 P1-3 的镜像错误）。

现行逻辑因此是「逐台：测量 → **只让这台自己**自证 → 自证不了换下一台重测」：

```
EIF / ADF  → 直接定案
双超时     → 这台自证 change_port
             证成 → APDF（记账写明"由测量服务器 X 自己正向证明"）
             证不成 → 换下一台重测（不是拿别人的证据背书）
全部证不成 → unknown + 写明已试哪几台
```

**一条容易漏的资格条件**：若服务器的 `OTHER-ADDRESS` / `CHANGED-ADDRESS` 落在私网
（实测 `stun.freeswitch.org` 某些 DNS 实例给出 `10.10.0.62:443`、
`stun.sonetel.com` 给出 `172.31.9.136:3479`），预热等于打空，随后 `change_port`
必然"无响应"。这时若当成"服务器不实现"，结论就被一条 DNS 记录决定了。所以这类
服务器是**没资格**当证明者/测量者的（`viable=False`），应跳过换下一台 —— 这与
"端口号 < 1024 就排除"不是一回事：`143.198.60.79:443` 是公网地址且实测可用，
按端口一刀切会误杀它。

## 四、测试纪律：异常路径的代码，必须配一个注入式用例

三次事故，同一个形状 —— **代码写了、但那条分支从来没被执行过**：

| 事故 | 表现 | 为什么单测没抓到 |
|---|---|---|
| P1-19 预算压缩 | 预算不足时把单包超时压到 `remain`，于是"没等够"被记成"被 NAT 过滤"，受限锥型→端口受限锥型 | 替身瞬时返回，永远走不到"预算将尽" |
| `_probe_one` | 误用 `r.supports_change_request()`（`BindingResult` 只有 `supports_rfc5780`），单测全绿，真机 CLI 直接 traceback | 替身只会调用你认为存在的方法 |
| 离群复核 | 复核分支里误写 `target.label`（`MappingSample` 只有 `server`），一触发就 AttributeError 崩在检测主流程 | 复核分支此前从未被触发过 |

**规则**：任何"只在异常/边界路径上才走到"的代码，必须配一个**注入式**用例 ——
主动构造出那个条件，而不是等它自然发生。

现有可复用的注入手段（`tests/nat_testkit.py`）：

| 手段 | 注入的现实条件 |
|---|---|
| `FakeStunNetwork(filter_mode="adf"/"apdf"/"eif")` | 三种 NAT 过滤策略 |
| `drop_first={(True, True)}` | 某个 CHANGE-REQUEST 的首包丢失 |
| `change_port_supported=False` | 服务器不实现 change_port |
| `other_unreachable=True` | 宣告了 OTHER-ADDRESS 但实际回不来 |
| `response_latency=0.3` + `FakeClock` | 服务器时延逼近/超过预算 |
| `AnomalousSampleNetwork`（`tests/test_robustness.py`） | 某个目的首次回复的映射端口 +1（单包抖动） |
| `PerServerCapabilityNetwork`（同上） | 只有指定服务器会响应 change_port |

**另一条配套约定：提交前跑一次真机** `python -m natscope.cli --no-gateway`。
替身永远只会调用你认为存在的方法，真机跑的是完整调用链 —— 上表第 2、3 条都是
真机/注入用例才暴露的，而"3 个测量 socket"那个副作用只有真机能看出来。
