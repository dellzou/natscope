# NatScope — NAT 类型检测工具 需求与技术方案

> 版本：v1.0　编写日期：2026-11-12
> 目标平台：Windows 10 / 11 x64（单文件免安装）
> 代码仓库：GitHub 公开仓库

---

## 1. 项目目标

一款轻量的 Windows 桌面工具，用于准确判定当前网络出口的 NAT 类型，同时给出：

1. **传统四类型**（RFC 3489）：完全锥型 / 受限锥型 / 端口受限锥型 / 对称型（含"开放互联网""UDP 被阻断"两种特例）；
2. **现代行为模型**（RFC 5780）：**映射行为**（Endpoint Independent / Address Dependent / Address and Port Dependent）与**过滤行为**（同上三档）；
3. **网关端口映射能力**：UPnP-IGD、NAT-PMP、PCP 是否可用，以及能否成功取到外网地址；
4. 基于结论给出 **P2P 可用性总结**（游戏联机、BT、远程访问等场景）；
5. 结果一键导出 **TXT** 与 **JPG**。

## 2. 功能需求

### 2.1 STUN 服务器调度

| 编号 | 需求 | 说明 |
|---|---|---|
| F-01 | 内置服务器池 | 用户提供的约 87 个公共 STUN 服务器，去重后内置 |
| F-02 | 启动探测与分级 | 并发探测全部服务器，按 RTT 与可用性分为 **优选 / 备选 / 不可用** 三级 |
| F-03 | 优先使用可用节点 | 检测主流程优先使用"优选"级服务器，超时自动降级到"备选" |
| F-04 | 自定义服务器 | 支持手动添加 `host:port` 或 `stun:host:port`，可导入/导出列表，可启用/禁用 |
| F-05 | 探测缓存 | 本次会话内缓存探测结果，避免重复扫描 |

分级规则：
- **优选**：探测成功且 RTT ≤ 300 ms；
- **备选**：探测成功但 RTT > 300 ms，或首次超时、重试成功；
- **不可用**：重试后仍失败（超时 / DNS 失败 / 返回非 STUN 响应）。

### 2.2 NAT 检测

| 编号 | 需求 |
|---|---|
| F-06 | RFC 3489 四类型判定（Test I / II / III） |
| F-07 | RFC 5780 映射行为判定（至少两个不同 IP 的 STUN 服务器） |
| F-08 | RFC 5780 过滤行为判定（依赖 CHANGE-REQUEST 支持） |
| F-09 | 两种模型的交叉校验，冲突时在报告中显式标注 |
| F-10 | 本地地址 / 公网映射地址 / 映射端口可复用性 展示 |
| F-11 | IPv4 为主，IPv6 出口单独提示（若绑定 IPv6 成功则显示） |

### 2.3 端口映射能力探测

| 编号 | 需求 |
|---|---|
| F-12 | UPnP-IGD：SSDP 发现 → 取设备描述 → 查 WANIPConnection → GetExternalIPAddress |
| F-13 | NAT-PMP（RFC 6886）：默认网关 UDP/5351 请求公网地址 |
| F-14 | PCP（RFC 6887）：默认网关 UDP/5351，MAP opcode 协议能力探测 |
| F-15 | 三类结果各自独立展示：可用 / 存在但无权限 / 未发现 |

### 2.4 输出

| 编号 | 需求 |
|---|---|
| F-16 | 检测结果含**结论总结**（按类型给出场景化文案） |
| F-17 | 导出 TXT：纯文本，含时间、本地信息、服务器、全部测试项、结论 |
| F-18 | 导出 JPG：卡片式图片报告，配色跟随当前主题 |
| F-19 | 导出时默认文件名带时间戳，弹出保存对话框 |

### 2.5 界面

| 编号 | 需求 |
|---|---|
| F-20 | 窗口可拖动、可缩放、可最小化到任务栏 |
| F-21 | 浅色 / 深色主题，默认**跟随系统**，可手动切换 |
| F-22 | 检测过程实时进度与日志，不阻塞 UI |
| F-23 | 检测可中断 |

## 4. 协议依据

### 4.1 STUN（RFC 5389，兼容 RFC 3489 服务器）

- 报文头 20 字节：`type(2) | length(2) | magic cookie(4)=0x2112A442 | transaction id(12)`
- Binding Request = `0x0001`，Binding Success Response = `0x0101`
- 关键属性：`MAPPED-ADDRESS(0x0001)`、`XOR-MAPPED-ADDRESS(0x0020)`、`CHANGE-REQUEST(0x0003)`、`RESPONSE-ORIGIN(0x802B)`、`OTHER-ADDRESS(0x802C)`、`SOFTWARE(0x8022)`、`ERROR-CODE(0x0009)`
- 属性 TLV：`type(2) | length(2) | value`，value 按 4 字节对齐补齐
- CHANGE-REQUEST 标志位：`0x04` = change IP，`0x02` = change port

### 4.2 RFC 3489 四类型判定

| 测试 | 动作 | 判据 |
|---|---|---|
| Test I | 向服务器主地址发 Binding Request | 得到映射地址 |
| Test II | 发 CHANGE-REQUEST（change IP + change Port） | 收到响应 → 不限制外来 IP/端口 |
| Test III | 发 CHANGE-REQUEST（仅 change Port） | 收到响应 → 不限制外来 IP |

判定顺序：

```
Test I 失败                        → UDP 被阻断（Blocked）
映射地址 == 本地地址               → 开放互联网（Open Internet / 无 NAT）
向不同 IP 的服务器各取一次映射     → 映射端口变化 = 对称型（Symmetric）
Test II 成功                      → 完全锥型（Full Cone）
Test III 成功                     → 受限锥型（Restricted Cone）
否则                              → 端口受限锥型（Port Restricted Cone）
```

> 注：对称型必须先行判定。RFC 3489 原文把"换服务器后映射改变"作为对称型依据，若先判锥型会误报。

### 4.3 RFC 5780 行为模型

**映射行为**（向 ≥2 个不同 IP 的服务器各发一次 Binding Request，比较 XOR-MAPPED-ADDRESS 的 IP:Port）：

| 现象 | 结论 |
|---|---|
| 全部相同 | Endpoint Independent（EIM，端点无关） |
| 同服务器不同端口 → 端口变；不同 IP → 端口再变 | Address Dependent（ADM） |
| 目的 IP 变即端口变 | Address and Port Dependent（APDM） |

**过滤行为**（对同一服务器的辅助地址发 CHANGE-REQUEST）：

| 现象 | 结论 |
|---|---|
| change IP+Port 有响应 | Endpoint Independent Filtering（EIF） |
| 仅 change Port 有响应 | Address Dependent Filtering（ADF） |
| 均无响应 | Address and Port Dependent Filtering（APDF） |
| 返回 420 Unknown Attribute | 服务器不支持 RFC 5780，行为项标记"不可测" |

**两种模型的对应关系**（用于交叉校验）：

| 映射 | 过滤 | 等价传统类型 |
|---|---|---|
| EIM | EIF | 完全锥型 Full Cone |
| EIM | ADF | 受限锥型 Restricted |
| EIM | APDF | 端口受限锥型 Port Restricted |
| ADM / APDM | 任意 | 对称型 Symmetric |

### 4.4 端口映射协议

- **UPnP-IGD**：SSDP `M-SEARCH` → `239.255.255.250:1900`，ST=`urn:schemas-upnp-org:device:InternetGatewayDevice:1`；解析响应 `LOCATION` → 取设备 XML → 找 `WANIPConnection`/`WANPPPConnection` 的 controlURL → SOAP `GetExternalIPAddress`。
- **NAT-PMP**（RFC 6886）：UDP `网关:5351`，8 字节请求 `ver=0 | op=0 | reserved(2) | 0(4)`，响应含外网 IPv4。
- **PCP**（RFC 6887）：UDP `网关:5351`，24 字节头 `version=2 | R=0 opcode=1 | reserved(2) | lifetime(4) | client_ip(16)` + 36 字节 MAP 载荷；返回 `UNSUPP_VERSION(1)` / `NOT_AUTHORIZED(2)` / `SUCCESS(0)`。

网关地址获取顺序：① 解析 `ipconfig` 默认网关 → ② 回退尝试 `网段.1` 与 `网段.254`。

## 5. 技术选型

### 5.1 候选对比

| 方案 | 体积 | 依赖 | 协议实现难度 | UI 表现 | 结论 |
|---|---|---|---|---|---|
| Electron + Node | ~150 MB | Chromium | 低 | 好 | ✗ 与"轻量"冲突 |
| C# WPF / .NET 8 | ~60 MB（self-contained） | .NET 运行时 | 低 | 好 | ✗ 本机无 SDK，且运行时依赖重 |
| Tauri (Rust) | ~10 MB | WebView2 | 中 | 好 | ✗ 依赖 WebView2，编译链重，迭代慢 |
| **Python + tkinter + PyInstaller** | **~18–25 MB** | **无（打包内含）** | **低（标准库 socket/struct）** | 中（需自绘） | **✓ 选定** |
| Go + Fyne | ~25 MB | 无 | 中 | 中 | ✗ 本机无 Go 工具链 |

### 5.2 选定方案

- **语言**：Python 3.13
- **GUI**：标准库 `tkinter` + `ttk` 自绘扁平化风格（不引入第三方 UI 框架，避免运行时依赖）
- **网络**：标准库 `socket` / `struct` / `selectors` / `concurrent.futures`，协议全部手写，便于审计与跨版本兼容
- **图片导出**：`Pillow`（唯一第三方依赖，仅用于 JPG 绘制）
- **打包**：`PyInstaller --onefile --windowed`，附 ico 图标
- **测试**：`unittest`（协议编解码单测 + 真实网络冒烟测试分离）

选择理由：tkinter 是唯一能做到"零运行时依赖 + 单文件 < 30 MB + Win10/11 全兼容"的 GUI 方案；协议层为纯标准库，后续若换 UI（WPF/Wails）可直接复用。

### 5.3 代理说明

STUN / NAT-PMP / PCP 全部走 **UDP**，HTTP 代理（如本机 `127.0.0.1:7890`）**无法代理 UDP**，因此：

- `7890` 代理**仅用于** git 推送、pip 安装等 TCP 场景；
- 软件运行时的 NAT 测试必须**直连**，走代理会得到代理服务器的映射结果，测试无意义；
- 若系统开了 TUN/透明代理，需临时放行 UDP 或关闭，否则结果反映的是代理出口。

## 7. 验收标准

1. 在开启 NAT 的家宽 / 手机热点 / 公司网三种环境下，四类型判定结果与已知结论一致；
2. RFC 5780 行为项在支持的服务器上可给出三档结论，不支持的服务器明确标注"不可测"而非误报；
3. 全部测试项在 30 s 内完成（服务器探测 10 s + 检测 20 s 上限）；
4. 断网、DNS 污染、UDP 全阻断三种异常下不崩溃，给出可读错误；
5. 导出的 JPG 在浅色/深色主题下文字均清晰可读。
